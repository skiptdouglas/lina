# Sample data

Synthetic telemetry for `CASE-DEMO-001`, generated by
[`scripts/generate_demo_data.py`](../scripts/generate_demo_data.py):

```bash
make demo-data          # writes sample-data/case-demo-001/
```

All of it is fabricated. Addresses come from the documentation ranges
(`203.0.113.0/24`, `198.51.100.0/24`), and no file contains real malware or
real personal data.

Plus a ~60-second beacon with jitter in the Zeek data, so Sprint 5's beacon
detector has a real signal to find.

## Files

| File | Source type | Contents |
|---|---|---|
| `sysmon-operational.jsonl` | `SYSMON` | Events 1, 3, 7, 10, 11, 13, 22 |
| `windows-security.jsonl` | `WINDOWS_SECURITY` | 4624, 4648, 5140, 1102 |

| `suricata-eve.jsonl` | `SURICATA` | EVE alerts across the intrusion |
| `MANIFEST.json` | — | Per-file SHA-256; TRACE must reproduce these digests |

`MANIFEST.json` is the point of the exercise: the digests it records are what
`POST /api/v1/evidence` computes on ingest and what
`GET /api/v1/evidence/{id}/verify` recomputes later. If they ever disagree,
the object has changed.

Generated files are git-ignored — regenerate them, don't commit them.
