# TRACE — Security

Security is part of the architecture, not a later sprint. A forensic platform
holds the most sensitive data an organisation has: full endpoint telemetry,
credentials in command lines, and the investigation itself.

---

## 1. Threat model (abridged)

| Adversary | Concern | Control |
|---|---|---|
| External attacker | Reach the API, exfiltrate evidence | AuthN on every route, no anonymous write, rate limiting, TLS at the edge |
| Compromised analyst account | Mass evidence download, identity reveal | RBAC, per-action audit, reason-required actions, rate limits |
| Insider under investigation | Tamper with evidence to hide activity | Immutable object storage, SHA-256 verification, hash-chained audit |
| Malicious evidence | Malware in an uploaded artifact executes on the server | Bytes are never executed, never rendered, never auto-extracted; parsing is sandboxed (Sprint 2) |
| The LLM / model provider | Sensitive identifiers leak to a third party | AI Privacy Gateway: pseudonymise + field-strip before egress |
| Cross-tenant leak | Tenant A reads Tenant B's case | `tenant_id` on every row, enforced in repository helpers |

## 2. Authentication

Pluggable via `TRACE_AUTH_MODE`:

* `token` (default) — `Authorization: Bearer <token>`. Tokens are supplied
  through `TRACE_API_TOKENS` (JSON, read from the environment or a mounted
  secret) and compared with `secrets.compare_digest`. Tokens are **never**
  logged, and are redacted from error output.
* `dev` — injects a full-privilege local principal for development.
  **Refuses to start if `TRACE_ENV=prod`** and emits a startup warning on
  every boot.
* `oidc` — planned (Sprint 7). The `Authenticator` interface exists so the
  swap does not touch route code.

There are **no credentials in this repository**. `docker-compose.yml`
declares secrets as `${VAR:?...}` so the stack fails loudly rather than
booting with a default password. `make init` generates random local secrets
into `.env`, which is git-ignored.

## 4. Tenant isolation

Every first-class row carries `tenant_id`, taken from the authenticated
principal — never from the request body. Repository helpers take the
principal and apply the filter; a cross-tenant fetch returns **404**, not
403, so existence is not disclosed.

---

## 5. Evidence handling

* Uploads stream to a spooled temp file with an enforced byte cap
  (`TRACE_EVIDENCE_MAX_UPLOAD_BYTES`, default 5 GiB); the cap is checked
  *while* streaming, not from `Content-Length`.
* Storage keys are generated by TRACE from `tenant/case/evidence_id/` plus a
  sanitised basename. Client path traversal cannot influence the key.
* Uploaded bytes are never executed, never expanded (no automatic zip/archive
  extraction), and never returned with a browser-renderable content type:
  downloads are served `application/octet-stream` with
  `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`.
* Deletion requires `evidence:delete` and is refused while `legal_hold` is set.
* YARA scanning of uploaded files (Sprint 4) runs in a resource-limited,
  network-isolated worker — never in the API process.

## 6. Audit and chain of custody

* Recorded actions: `COLLECT` `STORE` `VERIFY` `VIEW` `PARSE` `SEARCH`
  `EXPORT` `DOWNLOAD` `AI_ACCESS` `IDENTITY_REVEAL` `REPORT` and the
  case/auth lifecycle.
* Records are hash-chained: `record_hash = sha256(canonical_json(record) || prev_hash)`.
  `GET /api/v1/audit/verify-chain` reports the first broken link.
* `TRACE_AUDIT_FAIL_CLOSED=true` (default) means a request whose audit write
  fails is rejected. Silent auditing is worse than no auditing.
* Audit records are never updated or deleted through the API — there is no
  such route.
* The audit chain head is periodically committed to an anchored transparency
  log, so tampering stays detectable even when the operator of TRACE is the
  one tampering (docs/ANCHORING.md).

## 5a. Parsing untrusted evidence

Evidence is attacker-influenced by definition — it came from a compromised
machine — so parsing treats every artifact as hostile input.

* Reads are **constant memory and bounded** on four axes: total records, total
  bytes, single-record bytes, and the size of a served raw record. Exceeding a
  limit truncates and **says so** in the parse report; silent truncation would
  read as "that's all there was".
* Malformed records are counted and skipped, never fatal. One corrupt line in a
  recovered log must not cost the other 400,000.
* Parsers never execute, expand or render content. No archive extraction, no
  templating, no dynamic dispatch on attacker-controlled field values.
* Raw records are served `application/octet-stream` with `nosniff`. Content
  from a compromised machine is not trusted markup.
* Record locators are validated against a strict grammar, refused past the end
  of the object, and size-capped — a provenance pointer, not an arbitrary read.
* Parsing runs **in-process** today. Limits bound the damage from a parser bug
  but do not isolate it; sandboxed worker containers are the follow-up and are
  listed in the gaps below rather than implied to be done.

## 6a. Evidence anchoring

* Only a **32-byte Merkle root** is ever published to a ledger. No evidence,
  no manifest, no case identifier, no filename (ADR-0007). The
  `AnchorBackend.submit` signature makes this structural, and a test asserts it.
* The Ed25519 log signing key is read from a mounted PEM or an environment
  secret, never from source. `TRACE_ANCHOR_ALLOW_KEY_GENERATION=true` is
  refused when `TRACE_ENV` is staging or prod — an ephemeral key makes every
  tree head unverifiable after a restart.
* Losing the signing key does not invalidate past anchors; leaking it lets
  someone sign tree heads in your name. Treat it as a code-signing key. A
  `KmsSigner` interface exists for deployments needing the key out of process;
  it raises rather than falling back to something weaker.
* `anchor:create` is separated from `anchor:read` because publishing costs
  money on some backends. Auditors get read, not create.
* Each anchor records its **independence**; a `local` anchor is self-attested
  by TRACE and is never presented as third-party evidence (ADR-0009).
* Right to erasure remains satisfiable: deleting the evidence and its manifest
  leaves only a root, which reveals nothing. The proof for that entry stops
  verifying, which is the correct outcome.

## 7. AI boundary

1. The frontend has **no** model credentials and cannot reach a provider;
   `Content-Security-Policy` on the UI restricts connections to the TRACE API.
2. All model traffic passes `ai/privacy_gateway.py`:
   pseudonymise → strip prohibited fields → send → validate response →
   re-attach evidence references.
3. Prohibited-by-default fields (configurable, deny-list *and* allow-list):
   raw credentials/secrets in command lines, authentication tokens, full
   email bodies, personal identifiers, and any field not required for the
   question asked.
4. Every model call writes an `AI_ACCESS` audit record with the provider,
   model, redaction profile, and the evidence scope supplied.

## 8. Transport, headers, and input

* TLS terminates at the edge (reverse proxy / ingress). Compose ships HTTP for
  local development only; this is stated in the README, not implied.
* Security headers on all responses: `X-Content-Type-Options`,
  `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`,
  and a restrictive CSP on the UI.
* CORS defaults to the UI origin only; `*` is rejected when `TRACE_ENV=prod`.
* All request bodies are Pydantic-validated; unknown fields are rejected.
* Three endpoints are deliberately unauthenticated so that orchestrators can
  probe the service: `/health`, `/api/v1/health/ready` and
  `/api/v1/capabilities`. They expose liveness, dependency up/down and the
  implemented-feature map — never case, evidence or telemetry data. Every
  other `/api/v1` route requires a principal, which
  `tests/unit/test_auth_rbac.py` asserts by sweeping the OpenAPI schema.
* Rate limiting is per-principal token bucket. The MVP implementation is
  in-process (correct for one API replica) and documented as needing a shared
  store for horizontal scale.

| Field-level encryption at rest in ClickHouse | later |

Report vulnerabilities via `SECURITY.md` contact in the repository root
README rather than a public issue.
